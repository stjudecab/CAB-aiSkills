# Genomic Regions Correlation

## Purpose

Run GenometriCorr on two BED files and write reciprocal correlation reports,
visualizations, and run metadata in a UTC timestamped output directory.

## When Not to Use

Do not use this skill for peak calling, genomic-feature annotation, differential
testing, motif analysis, or correlation of signal tracks. The inputs must be
precomputed genomic regions.

## Required Inputs

- `query`: BED file containing the first region set.
- `reference`: BED file containing the second region set.
- `genome`: one of `hg19`, `hg38`, or `mm10`; ask when it is not supplied.
- `outputPrefix`: descriptive prefix recorded in metadata.

BED files must be readable by Bioconductor `rtracklayer::import`; use standard
chromosome names and valid interval coordinates. The wrapper validates file
existence but GenometriCorr performs the format and coordinate validation.

## Workflow

1. Resolve query and reference paths relative to `--inputDir` when they are not absolute.
2. Validate both files, labels, run ID, and the selected genome build.
3. Run a dry run first. It does not create output directories, stage inputs, create conda environments, or execute R.
4. With `--run`, stage the two inputs as symlinks under `linkedInputs/` or copy them when `--copyInputs` is requested.
5. Use the configured conda environment or `--noConda` and run the bundled `scripts/genometriCorr.r` locally, or write and submit an LSF job script with `--executor bsub`.
6. Verify all four expected PDFs for local execution and report the run directory and metadata.

Read [references/workflow-and-inputs.md](references/workflow-and-inputs.md) when
choosing labels, interpreting outputs, or troubleshooting package and genome
compatibility.

## Commands

```bash
python run_genomic_regions_correlation.py \
  --inputDir regions \
  --query gained.bed \
  --reference lost.bed \
  --genome hg38 \
  --outputRoot agentResults \
  --outputPrefix gained_vs_lost
```

Add `--run` to execute. Use `--condaEnv` and `--condaYaml` to select an
environment, `--condaPrefix` for an existing environment path, or
`--createCondaEnv` to create a missing environment and install upstream
GenometriCorr. Use `--noConda` only when
`Rscript` and all required R packages are already available in the current
shell. Use `--executor bsub` with `--queue`, `--project`, `--proc`, `--mem`,
and `--jobName` only when LSF is configured for the current user.

## Outputs

Each execution uses:

```text
<outputRoot>/genomic-regions-correlation-YYYYMMDDTHHMMSSZ/
├── linkedInputs/
├── input-symlinks.tsv
├── <queryLabel>_versus_<referenceLabel>.projection.pdf.pdf
├── <queryLabel>_versus_<referenceLabel>.vis.pdf
├── <referenceLabel>_versus_<queryLabel>.projection.pdf
├── <referenceLabel>_versus_<queryLabel>.vis.pdf
└── genomic-regions-correlation-run-metadata.json
```

The exact PDF names are generated by the R script from the labels. The metadata
records original and staged inputs, labels, genome, executor, resource options,
commands, expected outputs, status, and run ID. LSF runs also include
`<jobName>.commands.sh` and return `status: submitted` before asynchronous PDF
files exist.

## Quality Checks

- Confirm both BED paths exist and are distinct.
- Confirm the genome build matches the BED chromosome naming and intended analysis.
- Inspect the metadata command and all four reciprocal PDF outputs after execution.
- Treat R package, sequence-style, or chromosome mismatch errors as analysis failures; do not report a successful correlation without the PDFs.

## Failure and Escalation

If the genome or either BED file is missing, ask for it. If the conda environment,
Rscript, GenometriCorr, or the selected TxDb is unavailable, report the exact
missing dependency and preserve the dry-run command. Do not install packages
from the network without explicit user approval.
